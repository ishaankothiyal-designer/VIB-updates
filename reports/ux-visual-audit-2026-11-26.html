VIB UX and visual audit

Owner: Vikas Chauhan
Last updated: 26 November 2026

Background

We audited the current local presentation from the first screen through registration, sample selection, report reading, photos and buyer guides. We kept the selected navy and gold opening, ivory registration section, pale-blue editorial sections and scroll-led story.

We fixed five frontend issues found in this audit. We inspected all 16 static routes at desktop and mobile widths. The real vehicle service remains outside this presentation scope. This file embeds its screenshots and can be opened without a website login or a separate image folder. It has not been publicly hosted.

Journey today

Understand VIB → enter a registration or choose a sample → read the records → inspect photos and guides.

1. Understand the product. Health: good.

The opening names vehicle history reports and uses several vehicle examples. The paper treatment and compact controls match the selected direction. We checked all four card states at 320px with no overlap between the card and its actions.

2. Enter a registration. Health: frontend corrected; service intentionally unavailable.

We collect only the typed example registration in the page. The widget makes no lookup request and does not store or send the registration. Findings 1, 2 and 5 apply here. The field now has a clear invalid state, a linked error message and readable supporting text. A valid-format entry offers the sample journey without pretending that a real vehicle was checked.

3. Choose a sample. Health: good.

The example cards name the vehicle and the question to investigate. The all-samples disclosure exposes the remaining choices. We followed the entry alternative to the chooser and then opened the Creta report.

4. Read the report. Health: corrected.

Finding 3 is marked on these screenshots. The shorter notice gives space back to the vehicle details. We retain the fictional-history and preset-score context. The separate score and photo notes still state their limits. Finding 4 fixes word separation in heading text for reading tools.

5. Inspect the evidence while scrolling. Health: good.

On desktop, the active explanation and the visible evidence card match. We checked all six states and the return to the first state. Reduced motion removes the decorative stage and leaves six original evidence cards visible. Mobile keeps each card in reading order.

6. Inspect photos and dated readings. Health: good.

Across all ten sample reports, we selected the dashboard photo, opened and closed the viewer with Escape, moved backward and forward through the mileage readings, and collapsed and reopened service invoices. The photo viewer fits the 320px viewport and its controls have 44px height.

7. Read a guide and navigate. Health: good.

All three guide contents links reached their second section. The mobile menu opens, exposes four 48px navigation links, and closes with Escape. We kept the shared header, footer, paper surfaces and typography.

How we verify the result

We do not use a screenshot or a passing build as proof of a working backend or full accessibility compliance. We checked the local frontend using fresh Chrome captures, direct input and keyboard actions, source checks and fixture reconciliation.

  • 32 route views: 16 pages at 1440 × 900 and 390 × 844. No horizontal document overflow, broken images or removed operator names. Every route has one main heading and a shared header and footer.
  • Additional narrow checks at 320 × 800: four hero-card states, report, registration, menu, guide and photo viewer.
  • 15 Python tests and all resource, fragment, ARIA-target, fixture, photo, router, controller and JavaScript syntax checks pass. The 40 reference-photo hashes are unchanged.
  • Ten report interaction checks and three guide checks pass. The captured tab log contained no errors.
  • A bounded independent code review caught a whitespace regression, which we corrected before the final passing run. Browser observations are our own evidence; the review model did not run the browser.
